# Полное удаление procedural-стартапа: всё природное наполнение — из данных карты

## Конечный критерий
Запуск читает только авторские данные карты (`map.json:entities`). Runtime только изменяет состояние уже размещённых объектов. Нет `natural_scatter`, нет хардкод-координат светлячков, нет шаблонов «вокруг дерева», нет процедурного респауна с вычислением новых координат.

## Контекст (из инвентаризации)
Каркас уже data-driven: деревья (24), кролики (8), рюкзак, лут авторизованы в `green_valley.gdmap/map.json:entities` и читаются `AmbientSpawner._entities_of_kind()`. Три процедурных куска остались:
1. **`natural_scatter`-экспансия** (`map_document.gd:107-133`) — генерит траву/пищу вокруг деревьев (поэтому их нет в map.json как записей).
2. **Хардкод-кластеры светлячков** (`ambient_spawner.gd:141-151`) — 8 кластеров с литералами-координатами.
3. **Респаун по смещению от дерева** (`ambient_spawner.gd:225-246` + `foraging_service.gd`) — вычисляет новые координаты при сборе/убийстве.

Ключевое упрощение: `MapDocument.to_json()` уже не пишет `natural_scatter` (он в skip-list `map_document.gd:94`) — экспансия при `from_json` разворачивает его в entities, а сохранение их пишет. Поэтому миграция green_valley = open+save.

## Риски/заметки
- **Баланс:** отключение респауна делает еду/кроликов конечными — сознательное решение пользователя для прототипа.
- **Обратная совместимость сейвов:** старые сейвы с `forage_respawns`/`rabbit_respawns` читаются (лишние ключи игнорируются); собранные объекты просто не восстановятся.
- **Пользовательские карты с natural_scatter в `user://`:** перестанут разворачиваться — для прототипа допустимо, отмечу в F1.
