# Наполнение здания

## 1. Назначение и границы

**Наполнение** — режим модульного редактора здания для размещения визуальных
предметов, принадлежащих конкретному `BuildingBlueprint`: мебели, света, утвари,
текстиля, архитектурных деталей и предметов, визуально отражающих состояние дома.

Наполнение не является редактором карты и не создаёт самостоятельные игровые
сущности. Предметы в этом режиме не становятся целями логистики, рабочими
точками, объектами AI или источником истины для экономики. Эти обязанности
остаются у активных зон и систем поселения.

Например, костёр в наполнении может показать свет, погасшее состояние и
уложенные рядом поленья по уже известному состоянию дома. Он не хранит запас
дров, не принимает доставку и не расходует топливо сам.

Будущий режим ландшафта будет отдельным инструментом. Он получит размещение
мировых объектов, импорт зданий и spawn-записи живых существ; этот документ его
не определяет.

## 2. Формат

Предметы хранятся в массиве `objects` файла `.gdbuilding.json`.

```json
{
  "id": "furnishing_campfire_1",
  "asset_id": "campfire",
  "pos": [1.5, 0.0, 1.5],
  "rot": [0, 90, 0],
  "scale": [1, 1, 1],
  "properties": {
    "is_lit": true,
    "wood_stack_level": 2
  }
}
```

`id` стабилен в пределах чертежа. `asset_id` — стабильный идентификатор
ассета. `pos`, `rot` и `scale` — трансформ экземпляра. Значения `properties`
всегда JSON-безопасны.

Старое поле `anchor`, встречающееся в ранее сохранённых чертежах, при загрузке
допускается для обратной совместимости, но новый редактор его не создаёт и не
использует.

## 3. Размещение и трансформ

### 3.1. Сетка

Все предметы размещаются на сетке. Доступны шаги `1.0`, `0.5` и `0.25` м;
свободного размещения нет. По умолчанию ассет предлагает свой шаг, но автор
чертежа может переключить его для текущего размещения.

Позиции сетки — центры её ячеек: для шага `s` это `k·s + s/2`. Это сохраняет
предсказуемую композицию и не заставляет автора вручную выравнивать предметы.

Прижатия к грани или углу ячейки в наполнении нет. Если в будущем понадобится
магнит к стене, он будет отдельным контекстным действием, а не второй системой
координат.

### 3.2. Поворот и масштаб

Инспектор предоставляет поворот по X, Y и Z. Быстрое вращение панели и клавиши
`C` / `Shift+C` меняют только Y на 15°, потому что это частая операция для
предметов, стоящих на полу.

Масштаб всегда пропорциональный. Размер экземпляра обязан быть целым числом
блоков по каждой оси: для исходного размера `size_in_blocks` редактор разрешает
только такие коэффициенты, при которых `size_in_blocks * scale` целочисленен по
X, Y и Z. Дробный произвольный масштаб не допускается.

## 4. Каталог и режим работы

Режим редактора называется **«Наполнение»**. Каталог — один inline accordion, а
не два выпадающих фильтра. Группы и категории:

- **Экстерьер:** `camping`, `town`, `nature`;
- **Интерьер:** `furniture`, `lighting`, `utensils`, `cozy`;
- **Архитектурный декор:** `structural_decor`, `roof_decor`, `wall_decor`;
- **Оборудование:** резерв для будущих визуальных представлений оборудования.

Категория показывает число доступных ассетов. Пустая категория остаётся
приглушённой подписью «Скоро появится», но не является отдельной ступенью
навигации.

Инструменты:

| Инструмент | Клавиша | Действие |
|---|---|---|
| Поставить | `B` | Создаёт новый экземпляр выбранного ассета. |
| Выбрать | `V` | Выбирает предмет; перетаскивание перемещает его по сетке. |
| Удалить | `E` | Удаляет предмет под курсором. |

`Ctrl+D` создаёт явную копию, `Delete` удаляет выбранное.

### 4.1. Выделение и замена

В режиме «Выбрать» клик по предмету только выделяет его; повторный клик не
создаёт копию. Клик по пустому месту снимает выделение. Выбранный предмет
подсвечивается и открывается в инспекторе.

Выбор предмета синхронизирует каталог на его ассет, но не переводит редактор в
режим «Поставить». Замена — отдельная явная команда «Заменить выбранный объект».
Она сохраняет позицию, поворот и масштаб; свойства нового ассета начинаются с
его значений по умолчанию.

## 5. Ассеты, визуальные свойства и коллизии

`DecorAssetDef` (в коде историческое имя) описывает сцену предмета, размер,
категорию и настраиваемые `controls`. `DecorObjectController` применяет свойства
к сцене через декларативные `bind`; UI не зависит от имён конкретных узлов.

Свойства наполнения — только авторские визуальные параметры или отображаемое
состояние, переданное владельцем здания. Примеры: горит ли костёр, цвет света,
видна ли занавеска, уровень визуальной кучи дров. Они не заменяют состояние
экономики или симуляции.

У ассета будет явная политика коллизии:

- `none` — нет физической коллизии и препятствия маршрутизации;
- `box` — простая авторская коробка, наследующая масштаб экземпляра;
- `scene` — авторские `CollisionShape3D` внутри сцены для сложной формы.

По умолчанию — `none`. Коллизия не выводится автоматически из визуального
размера предмета: флаг, ковёр и огонь не должны становиться невидимой стеной.

## 6. Взаимодействие с активными зонами

Интерактивность здания определяется `place_zones` и `zone_anchors`, описанными
в основном документе модульного редактора. Предмет наполнения может визуально
помочь автору обозначить место работы или склад, но не заменяет якорь и не
создаёт его автоматически.

Если системе поселения нужно показать состояние здания, presentation-адаптер
передаёт его соответствующим предметам наполнения. Обратной записи из предмета
в доменную экономику нет.
